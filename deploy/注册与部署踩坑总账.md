

## 十一、一用户一实例（账号授权 / 配套网关）与公开同步（2026-11-16）

### 11.1 数据模型
- 表 `self_account_bindings` 增加 `kind`（password / oauth / gateway），默认 password。
- 解析器：`ParseAccountLines`（账号----密码）、`ParseOAuthToken`（回调链接或 token 每行一个）、`ParseGatewayKeys`（供应商----密钥，如 deepseek----sk-xxx）。
- 绑定创建时按模板 `authMode` 自动选解析器：account→密码、oauth→授权凭据、gateway→上游密钥。

### 11.2 面板开通器（D:\\控制面板总结聊天\\panel\\provision-bindings.mjs）
- 每 20s 拉 `/api/internal/bindings/pending`（头 `X-Internal-Secret: CRYPTO_SECRET`）。
- gateway（magpie）：用镜像 `ghcr.io/yetone/magpie:latest` 起独立实例，灌 `MAGPIE_API_KEY`（每用户独立 mgw- key）、`MAGPIE_PROVIDERS`（该用户上游凭据），startCommand 里执行 `magpie gateway-key add` + `magpie provider add` 后 `exec magpie serve`；域名 targetPort 3425；健康检查带 Bearer 调 `/v1/models`。
- oauth（cline 等）：直接用授权的 token 建该用户私有渠道（type 67），base 用模板固定地址，不暴露任何部署地址。
- password（ds2api）：独立实例 + `DS2API_CONFIG_JSON` + `auto_delete.mode=none` + `PORT=8080`，域名 targetPort 8080。

### 11.3 Railway 免费档的容量坑（重要）
- 单项目服务数有上限：871 项目到 5 个后 `serviceCreate` 报 `Free plan resource provision limit exceeded`。
- 修法：开通器改为**多项目池**（`pickTargets()`），遍历面板里所有 ready 账号，按「已有服务数最少」排序，建服务失败自动换下一个项目；后续变量/域名/部署都用该项目的 token 与 environmentId。
- 实测：magpie 一用户实例落在 842 项目（`f57b1651…` / `7e041c38…`）成功，域名 `magpie-u6-b5-production.up.railway.app`。

### 11.4 公开/私有必须双写
- 只改 binding.public 不会影响路由，必须同步 `channels.visibility`。
- 已修：`SetSelfBindingPublic` 返回 channelId 并同步 channels.visibility，控制器随后 `InitChannelCache()`。
- 已修：`DeleteSelfBinding` 返回 channelId，删除后把渠道 `status=3` 下线并刷缓存（否则删了绑定，渠道还在被路由）。

### 11.5 隔离验证（真跑）
- 私有 cline 渠道模型：qqtester01 调 `cline-free/mimo-v2.6-flash` → `503 model_not_found`，公共池列表里也没有 `cline-*`。
- 公开 magpie 渠道：公共池出现 `deepseek-v4.1-flash`，`owners[0]={user_id:6,name:linyan,avatar:...}`，调用会真实路由到该用户实例（上游返回 401，属于假凭据的预期）。
- 公开开关实时生效：`[22,23,24] → 收回 → [22,23] → 公开 → [22,23,24]`。
- 删除绑定：渠道 26 立刻 `status=3`。
