================================================================================
3. Contract alignment / deviations
================================================================================

- Channel type numbers: backend landed first — constant/channel.go assigns
  ChannelTypeWorkBuddy=65, ChannelTypeTrae=66 (64 = ChannelTypeOmniRoute).
  The placeholder constants were aligned to 65/66; only
  web/src/features/my-channels/constants.ts would need editing if renumbered.
- OAuth/import wire shapes verified against controller/channel_self_account.go:
  start -> {sessionId, authUrl, realm, expiresIn};
  poll(mode=preview) -> {done, credential: masked, key: full JSON};
  import_trae -> {done, credential: masked, key: full JSON, notice}.
  extractCredentialJson deliberately prefers `key` (full credential) over the
  masked `credential` preview object, and still tolerates credentials/
  credential/importToken shapes (fail-soft).
- Frontend uses mode=preview + form backfill (per M3-FE tasking) instead of
  the backend's optional mode=create shortcut; onChannelCreated is still
  handled if the backend ever returns {channel} in preview mode.
- oauth/start realm is not selectable in the UI (backend defaults when empty).
- Check-in model field names match model/checkin_account.go exactly
  (user_id/channel_id/agent_url/last_status/last_result/total_reward/
  last_checkin_day/created_time/updated_time). last_status "ok" is rendered
  as Success in the account card.
- /api/checkin/sites + /api/checkin/accounts routes are NOT yet registered
  backend-side at verification time (model layer landed; controller/router in
  progress). The page is fail-soft: sites fall back to built-in templates,
  account list shows an error state with retry until the routes exist.
