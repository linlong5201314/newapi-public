4. Decisions / deviations
================================================================================

1. /app/:slug for iframe/newtab modes returns the SPA shell (index.html, 200)
   instead of 404, so hard-refresh / direct navigation to the in-site viewer
   route (/_authenticated/app/$slug) renders. No target content is proxied in
   these modes. Unknown/disabled slugs still 404 (no config leak).
2. EXTLINK_SSRF_ALLOW_PRIVATE=true is an e2e-only escape hatch (same pattern as
   M3 checkin). Scheme + whitelist checks still apply. Production default is
   closed; the e2e target site runs on loopback.
3. Iframe mode embeds the target URL directly (blueprint §2), not /app/<slug>/;
   a slim-bar hint suggests "open in new window" when the target sends XFO.
4. ExtLinkAllowHosts supports exact hosts and leading-dot subdomain wildcards
   (".example.com"); empty = unrestricted (WARN at startup), per blueprint.
5. Architecture note: this fork's API auth is JWT Bearer (not cookie session);
   e2e used POST /api/user/login → access_token, setup wizard created root.
6. Commit bundles the previously uncommitted M1–M3 frontend feature dirs and
   their VERIFICATION-M{1,2,3}-FE.txt because shared files (routeTree.gen.ts,
   sidebar, i18n) now reference those routes; committing M4 alone would leave
   the tree non-buildable.
