D. 加密落地证据（代码路径）
================================================================================
- common/crypto.go：AES-256-GCM，key=SHA-256("new-api:crypto:v1:"+CRYPTO_SECRET)；
  存储格式 enc:v1:<base64url(nonce||ciphertext||tag)>；未配置 CRYPTO_SECRET 时
  EncryptSecret 返回 plain:<原文>，common.InitEnv 启动打印 WARN（含迁移提示）；
  DecryptSecret 对无前缀历史明文原样返回（无感迁移）。
- Node.ApiTokenEnc：CreateNode/UpdateNode 幂等加密（已加密/plain: 不重复加密），
  DecryptedToken 仅服务端使用；API 永不返回原文。
- CheckinAccount.CredJson：controller 新建/更新加密；service/checkin 四个站点
  （workbuddy/trae/custom/agent）读取解密；agent cookie 续期回写单独
  UpdateCheckinAccountCred 加密持久化（修复 M3 续期凭据未落库）。
- WorkBuddy(65)/Trae(66) channels.key：Insert/Update/BatchInsertChannels 与
  SaveCred 写回加密；GetKeys/GetNextEnabledKey/LoadChannelCred/
  SelfFetchAccountModels/GetChannelKey 透明解密。普通 API key 渠道维持上游行为。
- CloudflareApiToken Option：PUT /api/node/settings 加密后写 Option；
  nodedeploy.LoadOptions 解密使用；GetOptions 因 *Token 后缀被过滤，
  GET /api/node/settings 仅返回 cloudflareTokenConfigured 布尔。
- APInex 无独立渠道类型（仅签到账号），其凭据走 CheckinAccount.CredJson 已加密。

F. 决策与偏差
================================================================================
1. Node 模型在蓝图字段上增加 WorkspaceId/EnvironmentId/Repo/Branch/TargetPort/
   ServiceDomain/LastError：
   - WorkspaceId 是 Railway workspaceBilling/estimatedUsage 与 workspace 直查
     项目的必要入参（蓝图 §6 余额监控需要）；
   - Repo/Branch 供 githubRepoDeploy；TargetPort 供 serviceDomainCreate；
   - EnvironmentId/ServiceDomain 是部署后回写与后续 plan 定位所需。
2. plan/apply/failover/settings 响应字段用 camelCase（planId/serviceDomain/
   deploymentStatus/balanceAlertThreshold...），与蓝图 §7 请求体命名一致；
   Node CRUD 沿用 M1–M4 的 snake_case。
3. deploy/plan 的变量删除：默认 NodeDeployPruneVariables=false，删除动作仍展示
   但 skipped=true 且带 warning；只有显式开启 prune 才执行 variableDelete。
4. deploy 环境变量模板：Option NodeDeployEnvTemplate 优先；
   空则读 NODE_DEPLOY_ENV_TEMPLATE_FILE / deploy/.env.template；最后回落 Go 内置
   默认（含 MISE_PYTHON_GITHUB_ATTESTATIONS=false 构建坑预埋）。
5. plan 一致性：以 Node.UpdatedTime 作为配置版本；心跳/余额写库刻意不更新
   updated_time，避免 60s 巡检让 10 分钟 plan 频繁失效。
6. Worker KV 节点表格式：在保留已有 JSON 字段的基础上写
   {activeUrl, activeNodeId, updatedAt, nodes:[{id,name,url,healthy}]}；
   KV 键名 Option CloudflareKvNodesKey 默认 nodes。
7. Railway/CF 端点均可 mock：RAILWAY_GRAPHQL_ENDPOINT、
   CLOUDFLARE_API_ENDPOINT、NODE_DEPLOY_POLL_INTERVAL_MS（仅 e2e）。
8. 补齐 M4 遗留：middleware/access_token_routes.go 增加 /api/extlink/* 规则，
   否则既有 TestAccessTokenRouteRulesCoverEveryDashboardRoute 在 master 上失败。
9. Node 管理全部端点 RootAuth；access token 规则设为 session-only（平台级写
   操作不接受 PAT），GET /api/node 列表 token 只回 last-4 脱敏提示。
10. 自动 failover：余额/健康告警默认只生成 plan；仅 NodeAutoFailover=true 时
    以 system 操作者自动 apply，且 apply 前再次校验目标节点 enabled+healthy。
